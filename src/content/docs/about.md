Aporix is a public engineering notebook.

It is a place for notes, diagrams, experiments, and long-form writeups about AI infrastructure, inference systems, protocols, agent infrastructure, systems engineering, and the engineering philosophy behind complex systems.

The name is inspired by aporia: a state of uncertainty, contradiction, or unresolved questioning.

For me, engineering often begins from that state:

- a production issue is unclear
- a system boundary is unstable
- a model behaves differently under different batch sizes
- a protocol hides complexity behind a clean API
- a tool appears powerful but has no safety boundary
- a design looks elegant until it meets real traffic

Aporix is my attempt to turn those confusions into reusable systems.

## What This Site Is

This site is not a traditional blog. It is a growing knowledge system.

Small notes can become essays. Essays can become diagrams. Diagrams can become projects. Projects can become reusable engineering patterns. Patterns can become a way of thinking.

The goal is not to publish perfect articles. The goal is to build a durable public record of thinking, debugging, building, and refining.

## Core Sentence

**Aporix is where I turn confusion into systems.**

中文表达：**Aporix：把困惑沉淀为系统。**

## Long-Term Goal

Aporix should become a public technical knowledge base with three layers:

1. **Notes**: small observations and focused explanations.
2. **Systems**: structured models, diagrams, and technical frameworks.
3. **Artifacts**: projects, tools, experiments, and reusable engineering patterns.

It should become more than a portfolio. It should become an external memory for engineering judgment.
