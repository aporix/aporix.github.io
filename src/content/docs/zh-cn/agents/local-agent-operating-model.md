---
title: 本地 Agent 工作模型
description: 使用编码 Agent 时如何保持工程控制权。
---

编码 Agent 最有价值的时候，不是把它当成不可见的魔法，而是把它当成本地工程操作员。工作模型很简单：仓库要可读，任务要有边界，外部动作要可审计。

## 适合 Agent 做的事

- 阅读不熟悉的代码并总结系统形状
- 在明确范围内修改多个文件
- 修改后运行可重复检查
- 把零散记录整理成长期文档
- 执行迁移、清理和仓库维护

## 边界

Agent 不应该替代模糊的产品判断。它可以提出方案、检查代码、实现修改和验证结果，但仓库仍然需要清晰的人类意图。

有用的边界：

- 破坏性动作必须明确
- 非公开材料不进入公开仓库
- 使用小而清晰的提交
- 推送前运行本地检查
- 写清楚为什么清理，而不只是写做了什么

## 仓库卫生循环

```mermaid
flowchart LR
  Inspect["检查当前状态"] --> Decide["判断公开还是非公开"]
  Decide --> Edit["做有边界的修改"]
  Edit --> Verify["构建或检查"]
  Verify --> Publish["提交并推送"]
  Publish --> Prune["归档或删除陈旧内容"]
```

## 实用清单

- 这个仓库对陌生读者还有价值吗？
- README 是否不依赖隐藏上下文也能说明目的？
- 旧实验是否已经归档，而不是意外留在公开页面？
- 新文章是否只需要加 Markdown，不需要改代码？
- 公开 profile 是否指向维护得最好的内容？

这个账号的公开原则是：公开页面解释仍在维护的工作，避免暴露过期或非公开上下文。
