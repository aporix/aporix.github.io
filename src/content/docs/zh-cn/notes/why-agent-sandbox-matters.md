---
title: 为什么 Agent Sandbox 重要
description: Agent 自主性在进入生产信任前需要执行边界。
---

Agent 能行动时才真正强大。

它可以读文件、写代码、运行命令、调用 API、检查日志、修改配置，并持续执行多步任务。

风险也从这里开始。

## 没有边界的自主性不是工程

大家容易关注 Agent 是否聪明：

- 能不能规划？
- 能不能推理？
- 能不能使用工具？
- 能不能完成任务？

但在真实工程环境里，更重要的问题是：

- 它允许访问什么？
- 它允许修改什么？
- 什么动作需要批准？
- 什么可以回滚？
- 什么会被记录？
- 什么被隔离？
- 它错了怎么办？

如果回答不了这些问题，Agent 自主性不是能力，而是不受控的执行路径。

## Sandbox 提供什么

Sandbox 不只是安全机制，也是控制边界。

一个有用的 Agent sandbox 应该提供：

- 文件系统边界
- 命令执行限制
- 网络访问控制
- 环境隔离
- secret 保护
- 依赖控制
- 资源限制
- action log
- rollback 支持
- approval gate
- 可复现执行

目标不是阻止 Agent 有用，而是让有用行动足够安全，可以重复发生。
