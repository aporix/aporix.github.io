---
title: 工程笔记应该小
description: 为什么小笔记比等待完美长文更有价值。
---

常见写作错误是等一个想法完整后再写。

在工程里，这通常意味着永远不会写。

## 小笔记保存观察

很多有价值的工程洞察出现得很短：

- 奇怪 bug
- 有用命令
- 隐藏假设
- 权衡
- 设计边界
- 失败实验
- 调试路径
- 性能观察

如果不尽快写下来，它们会消失。

## 小笔记可以生长

```text
观察 -> 笔记 -> 聚类 -> 长文 -> 项目 -> 系统
```

五篇关于推理行为的笔记，可以变成一篇 inference systems 长文。三篇关于 Agent permission 的笔记，可以变成 Agent sandbox 设计。

Aporix 应该靠积累生长，而不是靠压力生产内容。
